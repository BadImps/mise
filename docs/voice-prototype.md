# Kokoro tablet prototype

## Purpose and status

Apply the agreed prototype-first recommendation: pre-render a fixed prompt,
then synthesize arbitrary step text using the **same Kokoro model, speaker,
phonemizer and speed**. Save both plus a comparison WAV containing the prompt,
exactly one second of silence and the complete step. Optionally play it on-device.

This is a separate developer APK (`com.badimps.mise.voiceprobe`) launched through
ADB instrumentation, not a Settings feature or a production release. It requires
no Internet permission. Model files are downloaded on the PC and copied once to
the device; subsequent synthesis happens locally. No microphone is involved.

## Pinned configuration

- sherpa-onnx Android AAR **1.13.8**, CPU, two threads.
- `kokoro-multi-lang-v1_0`, full-precision model, US English lexicon and espeak-ng.
- Carol: `af_heart`, speaker **3**; Sean: `am_michael`, speaker **16**.
- Speed **0.92**, 24 kHz output. Both personas share the model.
- The pinned archive has **54 voices**, per its README and generator. The older
  web documentation lists 53; the added voice is ID 53 and preserves existing IDs.
- Download: **349,886,476 bytes**; extracted model directory: **401,239,297 bytes**.
  The AAR is a separate **50,129,134-byte** developer dependency.
- SHA-256 values are pinned in `tools/prepare-voice-probe.mjs` and verified before
  extraction. Model/runtime binaries live in ignored directories, not Git or OTA.

1.13.8 retains the espeak text frontend used by this model pack. The inspected
2.0.1 API deprecates/ignores `dataDir`, so upgrading requires a separate
pronunciation/frontend comparison rather than silently changing the runtime.

## Build and run (PowerShell, from repository root)

```powershell
node tools/prepare-voice-probe.mjs
& android/gradlew.bat -p android -PvoiceProbe :voice-probe:assembleDebug :voice-probe:testDebugUnitTest :voice-probe:lintDebug
$env:ANDROID_HOME = 'D:\Android\Sdk'
& "$env:ANDROID_HOME/platform-tools/adb.exe" devices -l
node tools/run-voice-probe.mjs DEVICE_SERIAL both
node tools/run-voice-probe.mjs DEVICE_SERIAL sean "Stir gently, then simmer for five minutes."
```

Use the serial shown by ADB (USB debugging enabled on the tablet). The runner
installs only the prototype APK, copies the model with `adb push --sync`, plays
the comparison audio and retrieves results to `dist/voice-probe/results/SERIAL/`.
Each invocation has a ten-minute timeout. Stop a hung native run with:

```powershell
& "$env:ANDROID_HOME/platform-tools/adb.exe" -s DEVICE_SERIAL shell am force-stop com.badimps.mise.voiceprobe
```

Results include `carol/sean-prompt.wav`, `carol/sean-step.wav`,
`carol/sean-comparison.wav` and `report.json`. Reports record initialization,
fixed-prompt and fresh-step synthesis time, generated duration, real-time factor
and a **post-generation PSS snapshot** (not peak memory). RTF below 1 means
generation is faster than the duration of the resulting audio, not necessarily
that the wait before playback is acceptable. Each run replaces those results;
copy them elsewhere to preserve a benchmark.

Validate the retrieved artifacts independently:

```powershell
node tools/verify-voice-probe.mjs dist/voice-probe/results/DEVICE_SERIAL
```

This parses actual PCM WAVs and verifies non-silence, sample format, report duration,
the exact one-second zero-filled gap, and byte-for-byte preservation of the full
generated step in the comparison audio.

## What must pass on the physical tablet

1. Listen to both voices: prompt and step should have a consistent identity,
   loudness and pacing. Compare the prompt with `assets/voice/{persona}/step-1.wav`
   to determine whether existing Python-generated packs need regeneration.
2. Supply a previously unseen recipe step, including quantities and punctuation;
   check that every word is spoken and pronunciation is acceptable.
3. Run in airplane mode after copying the model. Confirm both voices still work.
4. Record first-run and repeat-run delays and memory on the actual tablet; an
   x86 emulator is not evidence of Samsung/ARM performance.
5. Decide whether full precision is acceptable before testing a smaller quantized
   model. Do not promise a smaller pack size or identical sound without measuring.

The prototype regenerates its fixed prompt before the fresh step to demonstrate
the shared pipeline. Production dialogue packs would be rendered ahead of time
with this pinned pipeline and shipped; recipes would remain dynamic. Existing
packs were generated by `tools/render-voice-pack.py` using Python Kokoro, not the
Voice Studio UI. Actual Voice Studio export matching remains a separate check.

## Integration after the listening/performance check

Add a resumable, hash-verified model download in Mise Settings, expose actual pack
status, and route all selected Studio speech through Kokoro. Pre-generate the next
step, correlate cancellation/completion to the cooking session, and only open the
microphone after successful playback. Samsung/system TTS can remain an explicit
fallback; it must not be represented as the same Carol/Sean studio voice.

Before distributing the embedded runtime, preserve component source/license
notices: Kokoro weights and sherpa-onnx are Apache-2.0, ONNX Runtime is MIT, and
the espeak-ng component has GPL obligations. Retain the downloaded pack's LICENSE
and review the chosen binary's corresponding-source requirements.

## Test evidence

User journey: hear a fixed prompt and arbitrary step in the same selected voice,
with a one-second gap and measurements that do not treat silent output as success.

- RED: `:voice-probe:testDebugUnitTest` failed because `ProbeAudio` did not exist.
- GREEN: three JUnit tests passed after implementation: exact sequencing/gap/full
  tail, rejection of empty/silent/non-finite samples, and explicit persona mapping.
- Android debug APK assembly and lint passed with the pinned native AAR.
- Device inference and listening evidence are recorded separately below; host
  unit tests do not establish pronunciation, perceived identity, or tablet speed.
- No coverage percentage is claimed for the JNI/Android integration. No checkpoint
  commits or release were made in this prototype task.

### Native test status

The first Android run correctly rejected the stale 53-speaker assumption; the
pinned archive README identifies 54. After correcting that check, the combined
synthesis/playback run produced Carol's three WAVs but exceeded the host's
120-second limit before reporting a result. That is **not a passing playback
test**. The prototype process was stopped, and a synthesis-only run for both
voices was started with a ten-minute bound to isolate synthesis from playback.
It completed with **PASS** for both voices. The runner now stops its own prototype process on
instrumentation timeout, and the latest APK emits phase progress messages.

The synthesis-only emulator result:

| Measurement | Carol | Sean |
|---|---:|---:|
| Fixed prompt synthesis | 2.877 s | 2.765 s |
| Fresh step synthesis | 9.451 s | 10.286 s |
| Step audio duration | 3.983 s | 4.574 s |
| Real-time factor | 2.373 | 2.249 |
| Post-generation PSS | 509,947 KiB | 557,392 KiB |

Shared model initialization took **108.359 seconds** on this x86 Android emulator.
These timings are too slow for immediate narration in this environment; they do
not predict physical-tablet performance. Native synthesis is proven, playback and
perceived identity remain unverified. The initial timeout is consistent with the
measured initialization plus synthesis time; it does not establish a playback bug.

Retrieved artifacts: `dist/voice-probe/emulator-results/`. Running
`node tools/verify-voice-probe.mjs dist/voice-probe/emulator-results` passed for both
personas: non-silent PCM, exact one-second gap, complete step preserved. These
checks establish audio structure, not that all words were pronounced correctly.
